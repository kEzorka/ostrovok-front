# Ostrovok Clone — дизайн проекта

## Замысел

Нужен локальный, полностью кликабельный и визуально максимально точный клон публичного пользовательского пути Ostrovok.ru для хакатона. Команда сможет позже подключить собственный backend без переделки фронтенда. Клон должен совпадать с наблюдаемым интерфейсом на десктопе и мобильном экране, но не должен обращаться к закрытым API Ostrovok, создавать реальные бронирования, собирать платежные данные или выдавать себя за официальный production-сервис.

## Цели

- Воспроизвести публичный фронтенд Ostrovok один в один на согласованных ключевых экранах: геометрию, отступы, сетку, цвета, типографику, радиусы, состояния контролов, карточки, drawers, sticky-элементы и responsive-перестроения.
- Реализовать сквозной сценарий: главная → настройка поиска → выдача → фильтрация/сортировка → карточка отеля → выбор тарифа → локальное подтверждение.
- Сделать основные элементы интерфейса действительно интерактивными, а не статичным макетом.
- Поддержать мобильный и десктопный layout.
- Оставить понятные точки расширения для будущей хакатонной логики.
- Положить в репозиторий декларативный граф агентов и системные промпты, пригодные для параллельного развития клона.

## Не-цели

- Полное воспроизведение всех публичных URL Ostrovok, корпоративного кабинета, справочного центра, блога, юридических страниц и партнёрских сервисов.
- Реальная авторизация, синхронизация избранного, рассылка писем, бронирование, оплата, возвраты и работа с персональными данными.
- Использование закрытого кода, приватных API или выгрузка каталога Ostrovok.
- Случайные рекламные кампании, персонализированные pop-up-виджеты и нестабильные production-цены, которые не являются частью основного пользовательского пути.
- Production-развёртывание под доменом, который можно спутать с официальным Ostrovok.

## Пользовательские маршруты

### `/` — главная

- Адаптивная шапка: текстовый логотип, избранное, уведомления, помощь, профиль, меню.
- Hero с вкладками «Отели и апартаменты», «Трансферы», «Для командировок».
- Поиск отелей: направление с локальным автодополнением, диапазон дат, комнаты/взрослые/дети, «Только апартаменты», тип поездки, кнопка поиска.
- Поиск трансфера: в одну сторону/туда-обратно, точки отправления и назначения, дата, время, пассажиры.
- Контентные блоки: преимущества, приложение, подписка и многоуровневый footer.
- Все второстепенные внешние ссылки либо ведут на `#`, либо открывают локальную информационную заглушку; интерфейс не отправляет данные наружу.

### `/search` — выдача

- Резюме запроса, тип размещения, переключение списка/карты, число найденных вариантов.
- Моковый каталог минимум из 12 объектов с изображениями, рейтингом, расстоянием, особенностями, ценой и состоянием избранного.
- Сортировка по популярности, рейтингу и цене.
- Фильтры: диапазон цены, тип объекта, рейтинг, звёзды, питание, бесплатная отмена, удобства и удалённость от центра.
- Фильтры немедленно пересчитывают список и число результатов; пустая выдача имеет отдельное состояние и сброс фильтров.
- Карта является локальной стилизованной панелью с маркерами и синхронизацией выбранного объекта, без внешнего картографического SDK.

### `/hotel/:slug` — карточка отеля

- Галерея, название, звёзды, рейтинг, адрес, расстояние до центра и кнопка локальной карты.
- Резюме поиска с возможностью изменить даты и гостей.
- Блок доступных номеров с фильтрами кровати/питания/оплаты/отмены.
- Тарифы с ценой, скидкой, условиями, остатком комнат и CTA.
- Описание, удобства, условия размещения, отзывы и похожие варианты.
- CTA ведёт только на локальный demo checkout.

### `/checkout/:rateId` — локальное подтверждение

- Сводка отеля, номера, дат, гостей и цены.
- Явная пометка «Демо: бронирование не создаётся».
- Кнопка подтверждения показывает локальное успешное состояние и не запрашивает ФИО, телефон, e-mail, карту или иные персональные данные.

### `/transfers` — моковая выдача трансферов

- Сводка запроса, 6 вариантов автомобиля, вместимость, багаж, время ожидания и цена.
- Сортировка и выбор варианта работают локально.
- CTA показывает демо-подтверждение без внешней отправки.

## Данные и состояние

- Все данные хранятся в типизированных fixtures mock-сервера внутри репозитория и выдаются фронтенду через HTTP API, совместимый с будущей заменой на backend команды.
- Параметры поиска отражаются в query string, поэтому страницу можно обновить или открыть по ссылке без потери состояния.
- Избранное и последнее состояние поиска хранятся в `localStorage` через небольшой версионированный адаптер.
- Расчёт цены детерминирован: базовая цена тарифа × число ночей × число комнат; никаких случайных значений после загрузки.
- Некорректные query-параметры нормализуются к безопасным значениям по умолчанию.

## Технологическое решение

Решение автора дизайна: React + TypeScript + Vite, React Router, обычный CSS с design tokens, Vitest/Testing Library и небольшой Express mock API. Зависимости должны оставаться минимальными; дата-пикер, dropdown гостей, фильтры и локальная карта реализуются компонентами проекта. Mock API возвращает временные тексты, цены и локальные изображения-заглушки. Закрытые ресурсы, production-код и private API Ostrovok не копируются.

Приложение разделяется по функциональным модулям (`home`, `search`, `hotel`, `checkout`, `transfers`), общему UI-kit и API-клиенту. Контракт mock API фиксируется в общих типах; будущий backend сможет заменить mock-сервер, сохранив JSON-схемы. Доменная логика фильтрации, сериализации query string и расчёта цены остаётся чистыми TypeScript-функциями и тестируется отдельно от React.

## Визуальная система

- Основные цвета, размеры, радиусы, границы и тени снимаются с видимого эталона Ostrovok и фиксируются design tokens; произвольная «похожая» стилизация не принимается.
- Ширины контейнеров, высота hero, размеры поисковой формы, карточек и sticky-панелей проверяются скриншотами в тех же viewport.
- Типографика должна совпадать по визуальной плотности, кеглю, высоте строки и весу; при недоступности фирменного шрифта используется метрически близкий локальный fallback.
- Брейкпоинты: мобильный до 767 px, планшет 768–1099 px, десктоп от 1100 px.
- Все интерактивные элементы имеют видимый focus, доступны с клавиатуры и снабжены корректными label/aria-атрибутами.
- Уважать `prefers-reduced-motion`; декоративные переходы не должны мешать навигации.

## Граф агентной разработки

В репозитории появится `agents/graph.yaml` с направленным графом:

1. `coordinator` — анализирует spec, дробит работу и сводит результаты; модель `gpt-6.1-sol`, высокая глубина рассуждений.
2. `recon` — поддерживает inventory экранов и состояний по публичному UI; модель `gpt-6-luna`, средняя глубина.
3. `design_system` — владеет tokens, UI-kit и responsive shell; модель `gpt-6.1-terra`, высокая глубина.
4. `booking_flow` — владеет доменной моделью, query state, fixtures и маршрутами поиска/отеля/checkout; модель `gpt-6.1-sol`, высокая глубина.
5. `visual_qa` — сравнивает браузерные состояния, проверяет accessibility и regression; модель `gpt-6-astra`, высокая глубина.

Граф: `coordinator → recon`; затем `recon → design_system` и `recon → booking_flow` параллельно; после их слияния `design_system + booking_flow → visual_qa`; замечания QA возвращаются владельцу соответствующего модуля, а финальное решение принимает `coordinator`.

Для каждого узла будет отдельный системный prompt с ролью, входами, разрешёнными файлами, обязательными проверками и форматом результата. Агенты не должны одновременно редактировать один файл; общие интерфейсы фиксируются coordinator до параллельной работы.

## Проверка качества

- Unit-тесты: query parsing, фильтрация, сортировка, price calculation, localStorage migration.
- Component-тесты: поиск, dropdown гостей, фильтры, favorite, rate selection, demo confirmation.
- E2E smoke: главная → Москва → фильтр → отель → тариф → demo success; отдельный сценарий трансфера.
- Visual QA на эталонных viewport `390×844`, `768×1024` и `1440×1000`: попарное сравнение референса и локального клона, отсутствие структурных расхождений и исправление заметных сдвигов до завершения.
- `npm run lint`, `npm run test`, `npm run build` и E2E smoke должны проходить перед завершением.

## Критерии готовности

Клон готов, если на эталонных viewport ключевые экраны визуально совпадают с публичным Ostrovok по структуре и оформлению, новый пользователь без объяснений проходит основной сценарий до demo success, выдача реально меняется от фильтров, состояние URL воспроизводимо, а проект запускается одной командой из README. Фронтенд общается только с документированным mock API, который команда может заменить своим backend. Любое действие, похожее на реальное бронирование или передачу данных, остаётся локальной демонстрацией.
